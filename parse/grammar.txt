# PASM grammar

A program consists of a series of lines. A line may end with a comment; a comment starts with a semicolon and runs
to the end of the line. Lines containing only whitespace and comments are ignored.

A line may contain an assembly directive, a data definition, a label definition, an instruction, or a label
definition followed by an instruction.

Example:

```
ORG 100h ; starts the program at address 100h

MOV AX, 1
; Ends the program
INT 20h
```

Numeric values may be bytes or words. Bytes can have values in the range -128..255. Words can have values in the range
-32768..65535. Numbers can be expressed as decimal numbers, or as binary, octal, decimal or hexadecimal with
the suffixes 'b', 'o', 'd', and 'h', respectively. A hexadecimal number may not start with a letter; add a zero on the
left if necessary.

Examples: 12, 42, 127, 7Fh, 0CAFEh, 1001b, 777o.

Strings are delimited with single quote signs ('). There are no escape characters.

Examples: '', 'a', 'abcde'

## Assembly directives

### `ORG` number

Changes the current position in memory to the given value.

Example: `ORG 100h`

### identifier `EQU` token token ...

Registers the given identifier so it will be replaced with the tokens whenever it's found in the source.

Example:

```
mem EQU BYTE PTR [BX + SI]
MOV mem, 1
```

## Data definitions

Data definitions start with a new label name and are followed by a `DB`, `DD`, or `DW` instruction.

Examples:

```
salutation  DB 'Hello',0Dh,0Ah,'$'
address     DW salutation
screen      DD 0b800h:0000h
```

## Label definitions

Label definitions consist of a label name followed by a colon. They may be in their own line, or they may be
immediately followed by an instruction.

Examples:

```
start:
    MOV AX, AX
end: JMP start
```

## Instructions

Some instructions take zero arguments, and they can be denoted by their name.

Examples:

```
PUSHF
CLI
POPF
RET
```

Some instructions take one or two arguments. The first argument is separated from the instruction name by one or
more spaces. The second argument, if it exists, is separated from the first by a comma.

Examples:

```
DEC AX
MOV BX, CX
```

Arguments can be numbers, labels, register names, segment names, or memory pointers. Labels represent the memory
address they point to. Numbers and labels can be operated on with the addition (+) and subtraction (-) operators.

The valid 16-bit registers are `AX`, `BX`, `CX`, `DX`, `BP`, `SP`, `SI`, and `DI`. The valid 8-bit registers are
`AL`/`AH`, `BL`/`BH`, `CL`/`CH`, and `DL`/`DH`. The valid segments are `CS`, `DS`, `ES`, and `SS`.

Memory pointers are specified by a combination of a base register, an index register and an offset, all between square
brackets. Memory pointers can be preceded by a segment name (followed by a colon) to change the pointer's segment.
Memory pointers can also be preceded by `BYTE PTR`, `WORD PTR`, or `DWORD PTR` to indicate that the position in
memory they point to contains a byte, word, or double word. This is not mandatory if it can be determined from context.

In instructions that take two arguments, generally the first argument holds the "destination" of the operation and
the second argument contains the "source".

Examples:

```
MOV AX, 1       ; puts the value 1 in register AX
MOV AX, [1234h] ; puts the content of the word in memory position 1234h in register AX
DEC BYTE PTR [BX] ; accesses the memory position contained in register BX and decrements the byte contained there
MOV AL, ES:[BP + SI + 1234]
```
